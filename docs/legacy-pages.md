# Legacy Pages

All 30 pages of docs/app-spec.md are built; the list under "Built in the New Look" at the end says where each one lives. **Since 2026-10-21 the site's look is the mascot-led one** (the home page, [storefront-design.md](storefront-design.md)): its tokens are app-wide, so every page already sits on the new paper and gold, but only Home and the public shell (header, footer, phone tab bar) are designed in it. The other pages in that list were built in the previous black-and-amber look and are redesigned a few per session (courses first), following the "Mascot" flow in storefront-design.md; until then a small fix goes in as is. The pages' app-spec features are in [app-spec.md](app-spec.md); what is not built yet (the Partner Enquiry form, courses without a price) is named in its Future Features and in [storefront-design.md](storefront-design.md), Loose Ends.
**Agents: read this before changing any file in a route or component listed here.** Find its row, follow its verdict below, and update this doc in the same commit when a row is done.

## Verdicts

| Verdict      | Meaning                                                                         | What to do when a task touches it                                                                                                                                                                                                                                                                                                                                      |
| ------------ | ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Redesign** | The feature is still right in [app-spec.md](app-spec.md); only the look is old. | **Small change** (a bug fix, copy, one field, a validation rule): make it in the page's current look, no redesign. **Anything that changes the layout or adds a section:** redesign the whole page first, following [design-flow.md](design-flow.md) and [storefront-design.md](storefront-design.md) (brief, shown to the user before UI code), then make the change. |
| **Rebuild**  | app-spec changed how the feature works, so the page's flow is wrong.            | Don't patch the old page. Build the app-spec page fresh in the new look (brief first), point the links at it, then delete the old route slice and its row here.                                                                                                                                                                                                        |
| **Retire**   | The feature is dropped in app-spec.                                             | Don't change it or build on it. If a task seems to need it, tell the user the feature is dropped. Delete it when the code refactor removes its feature, along with its row here.                                                                                                                                                                                       |

When a page is redesigned or rebuilt, remove its row and add it to the "Built in the new look" list at the end.

## Public Pages

No public page has an open verdict. The public shell was redesigned on 2026-10-21 (see the Home entry below).

## Built in the New Look

- Home (`/`): `app/routes/home/`, documented in [storefront-design.md](storefront-design.md) ("The Home Page", "Mascot"). Since 2026-10-21 it is the mascot-led page the owner approved on `/new-design` (that route is gone): the hero's bark, the steps trail, the run, the pinned «چی می‌تونم یاد بگیرم؟», the formats, the trainer and the closing «بریم؟». The loader only keeps `?ref=` (F7). The old rotating hero (`hero-state`), quick actions, promise strip, evaluation panel and the switched-off `NeedsSection`, `CourseGrid` and `TeamSection` were deleted (git keeps them).
- Public shell (`app/routes/layout_public/`): redesigned with Home on 2026-10-21. The header sits on the paper (the emblem and «زروان» with the descriptor; from `lg` دوره‌ها، درباره، تماس، راهنما, «ورود» or the signed-in person's cart and `PersonMenu`, and the gold «ارزیابی رایگان» pill); below `lg` it is an app bar and the floating tab bar (`tab-bar.tsx`: خانه، دوره‌ها، ارزیابی، تماس، بیشتر) carries the nav, with the «بیشتر» sheet (`more-sheet.tsx`) holding about, help, «همکاری با زروان», the rules once approved, the account and the contact links. The footer is a grained card band (brand and social links, three link groups, contact). «همکارها» left the header for the footer and the sheet. The shared mascot pieces are in `app/components/` (`MascotCut`, `ChalkBubble`, `EvaluationButton`, `GroundStrip`, `ChalkTicks`, `BrandEmblem`, `social-icons`).
- Evaluation Request (`/assessment`): `app/routes/assessment/`. A signed-in customer page: the dog's bubble guides the form, and the page turns into a receipt when it is sent.
- Dashboard (`/account`): `app/routes/account_home/`. A signed-in customer page: one card per dog, each with the dog's bubble saying its state and one main action, the dog's active enrollments and passed-course chips, and a link to Dog Detail.
- Dog Detail (`/account/dogs/:dogId`): `app/routes/account_dog_detail/`. A signed-in customer page: a header band where the photo fades into black and the dog's bubble draws itself in, with passed courses as medals, then enrollments, the certificates issued for finished courses (each with its link and QR code), the diary the trainer writes after each session (read-only, newest first), evaluation requests and a sticky column on desktop with the profile and the dog's **file card** (its number, the QR code that opens its private record, the link and a PNG to print).
- Shared pieces for those two pages: `DogPhoto` (`app/components/dog-photo.tsx`), `WithdrawEvaluationButton` (`app/components/withdraw-evaluation-button.tsx`) and `getDogStatus` (`app/lib/dog-status.ts`).
- Course Detail (`/courses/:slug`): `app/routes/course_detail/`. A public page: the course's facts and a buy card in the hero (the course's dog standing on it, the price on a chalk tag, no photo) where the customer's dogs are a radio list and the picked dog answers in a chalk bubble (it can take the course, or why not, with a way out), «افزودن به سبد» into the cart (`app/atoms/cart.ts`, kept in the account and mirrored in the browser), then what the course teaches, its lane and the free-evaluation ask.
- Cart (`/account/cart`): `app/routes/account_cart/`. A signed-in customer page: each dog packs its own bag (photo, the dog's bubble saying what it is about to start, its courses), items read fresh from `checkout.review` with unavailable ones marked with the reason and the way out, the server's total, «پرداخت» to the gateway, an optional «کی هماهنگ کنیم؟» card under the bags (weekdays and parts of the day as chips; a preference for the call, sent with «پرداخت» and kept on the payment, never a booking), and the gateway's result as a banner where the dog speaks (the page's one orchestrated moment; on `paid` the cart is read again, since the server took the bought items out when the payment settled).
- Buy a Course (`/buy`): `app/routes/buy/`. A signed-in customer page reached from the «خرید دوره» button at the top of the catalogue (a visitor is sent to sign in and back, the dog included): the customer's dogs as a picker (the choice is the address, `?dog=`), then every course on sale with the server's verdict for that dog from `checkout.dogCourses` (price and «افزودن به سبد» or «در سبد است», or each reason with the way out), and «دیدن سبد و پرداخت» once the cart holds something. See [app-spec.md](app-spec.md) F5.
- Purchases (`/account/purchases`): `app/routes/account_purchases/`. A signed-in customer page: one slip per payment, with a stub (date, status, total, reference, card) and a line per course with the dog, its enrollment status, or a plain note for a paid item with no enrollment.
- Account shell (`app/routes/layout_account/`): tabs «سگ‌های من», «سبد» (count badge) and «خریدها», bottom tabs on phones; the person menu is shared with the storefront header (`app/components/person-menu.tsx`). The public header (`app/routes/layout_public/`) knows the session: a signed-in customer sees the cart icon with its count and a person menu instead of «ورود یا ثبت‌نام».
- Dog Form (`/account/dogs/new`, `/account/dogs/:dogId/edit`): `app/routes/account_dog_form/`. A signed-in customer page where the dog's own page is written as the owner fills the form: a sticky column with its photo (the photo is the picker) or engraved tag, its name stamped in as it is typed, the facts line and a bubble that follows the section; the form in three sections with pill choices; birth date and breed shown as locked plates once the dog is evaluated. `segmented-choice` is retired (the pills live in the slice).
- Login / Register (`/auth`): `app/routes/auth/`. The home hero turned into a form: the dog's photo fills the page, the form sits in its dark half with no box, and a different dog asks at each step (the shepherd for the phone, the Malinois for the code, the puppy for the name); the photo crossfades and the bubble's words change. The flow, redirects and `?ref=` attribution are unchanged (the page now also remembers `?ref=` itself, as Home does).
- Course Catalogue (`/courses`): `app/routes/course_catalogue/`. A public page in the mascot look: the `peek` dog looks over a brick shelf of family pills and his bubble is the live result counter («۱۱ تا دوره دارم!», «برای «cgc» یه دوره پیدا کردم»); each family on the page is a sunken panel with its own dog, path and scenery beside or above its cards. The search is the header's (`HeaderSearch`, Persian-folded, on title, Latin name and summary), writing the same `q`; family and page live in the URL too (`?q=&family=&page=`); cards show the course a dog must have passed first; a free-evaluation ask closes the page. Shares `CourseCard`, `CourseFamilyFilter`, `Pagination` and `course-families` with `/buy` and the Admin.
- Profile Settings (`/account/profile`): `app/routes/account_profile/`. Shared by customers and partners. The person's own tag is engraved as they type (the initial disc, the name, the locked login number) with the stock dog leaning behind its top edge and its bubble following the focused card; two independent forms: the name (Better-Auth `updateUser`) and, for partners only, the Sheba (`partner.updateMine`, checked for format and checksum). The link is «تنظیمات حساب» in the person menu of both headers and the phone sheet (`PROFILE_LINK` in `app/lib/account-links.ts`), not a tab.
- Help and FAQ (`/help`): `app/routes/help/`. A public page, redesigned in the mascot look on 2026-10-21 (a dog per step, scenery instead of the stock photo): the dog on the phone says the key fact on the road («بعد از ثبت درخواستت، طلا باهات تماس می‌گیره»), a five-stop chalk road (free evaluation, courses open, pay, call and training, done) is both the overview and the index into six FAQ groups (the same numbered discs head the groups; a disc fills gold on `:target`), then an accordion of 18 questions whose ids are anchors (`/help#how-buying-works`, `#after-paying`, …; opening a question by hand writes its id into the hash) and a closing ask. The copy states no refund or cancellation rules, deadlines or calendar: the only money-back sentence is the answer to «اگه طلا نتونه سگمو بپذیره چی؟».
- Privacy (`/privacy`): `app/routes/privacy/`. A public page and a **placeholder** until the owner sends real legal text: it says only what the app does today. Redesigned in the mascot look on 2026-10-21 (the stock photo is gone): the guard dog by a locked chest, a sticky contents rail with the watching dog on desktop, what is stored (eight rows, plus the note that dog and evaluation photos are public by an unguessable link while evaluation videos are private), «کی چی رو می‌بینه» as three plates on a brick wall (you, the head trainer, a partner, with what the partner does not see), what the person can change, and the collapsed technical details; see [storefront-design.md](storefront-design.md).
- Dog Record (`/logbook`, `/logbook/:fileNumber`): `app/routes/logbook/`. A public page: the file-number lookup, and what a dog's QR code opens: «این پرونده خصوصیه» for everyone but the owner and the Admin, who are sent to their own page for the dog; if the owner has made the record public (not possible until the owner approves the consent wording, `app/lib/public-record.ts`) it shows the dog's name, breed and age, finished courses, valid certificates and the entries marked public. See [app-spec.md](app-spec.md) F14.
- Certificate Check (`/certificate/:number`): `app/routes/certificate/`. A public page for the QR code on a certificate: valid (course, day, head trainer, number), revoked (only that it is), or not found; never the owner, never cached or indexed. See [app-spec.md](app-spec.md) F14.
- Rules (`/rules`): `app/routes/rules/`. A public page that exists only once the owner approves the wording (`app/lib/site-rules.ts`): until then it answers 404 and nothing links to it. See [app-spec.md](app-spec.md) F13.
- About (`/about`): `app/routes/about/`. Redesigned in the mascot look on 2026-10-21: the head trainer's taped photo on a brick wall with the waving dog, three fact scenes, the family dogs' lineup into the catalogue (from `course.list`, left out if that fails) and a closing card. Built only from the business card; see [storefront-design.md](storefront-design.md).
- Contact (`/contact`): `app/routes/contact/`. Redesigned in the mascot look on 2026-10-21: the phone number as the hero with the dog on the phone, the three profiles as signs on a brick wall with the letter dog and the mailbox, and the Tehran band into the footer. Built only from the business card; see [storefront-design.md](storefront-design.md).
- Partner Enquiry (`/join/partner`): `app/routes/join_partner/`. A public page with **no form**: there is no enquiry API and only the Admin creates partner accounts (app-spec F1), so the page explains the partnership (referral link, QR code, phone leads, the commission on a customer's first purchase, paid outside the app) and tells a clinic, groomer or pet shop to phone the center. Redesigned in the mascot look on 2026-10-21 (the stock photo is gone): a street of the shop owner's places with the groomed dog, the three ways in on a brick wall under the shop counter, the steps on a chalk path, the commission plate and a phone ask. Its main action is the call, not the free evaluation.
- Admin shell (`/admin`, `app/routes/layout_admin/`): guarded to the Admin; a short top bar (logo, «مدیریت» tag, the shared person menu), a rail at the start side on desktop and bottom tabs on phones, both read from `admin-nav.ts`. The eleven pages are in two groups with a hairline between them (the daily work: Dashboard, Evaluations, Enrollments, Payments, Partners, Dogs; then the setup pages: Courses, Users, SMS, Settings); with more than four pages the phone's tabs keep the first three and the rest open from «بیشتر», a bottom `Sheet` (its tab carries the sum of the counts hidden inside). `/admin` is the Dashboard; `roleHomePath` sends the Admin there. The «ارزیابی‌ها» tab carries the count of requests waiting. Shared Admin pieces live in `app/components/` (`admin-page-header`, `admin-filter-pills`, `admin-empty-state`, `customer-contact`, `dog-evaluation-stamp`) with `useAdminAction` in `app/hooks/`.
- Admin Payments (`/admin/payments`): `app/routes/admin_payments/`. Display only: every payment as a slip (paid ones with their items, failed and pending ones collapsed to one line), filters and paging in the URL (`?view=&page=`), and a flagged **paid, not enrolled** item drawn as a torn slip (dashed destructive outline) with the customer's number to call, plus a strip at the top with how many there are and their sum. The wording never says the customer is owed: the flag can't be cleared, because the app records no refunds.
- Admin Enrollments (`/admin/enrollments`): `app/routes/admin_enrollments/`. The call sheet: one block per customer (their name and number as a call button, with their enrollments beside it), so a customer who bought two courses is dialled once. Status pills and pages live in the URL (`?status=&page=`); each active line has «تمام شد» and «لغو», each with one confirm dialog and no form, and a finished line says how and when it ended.
- Admin Evaluations (`/admin/evaluations`): `app/routes/admin_evaluations/`. The contact sheet: each request is a row with the dog, the customer's number, up to three photo thumbnails and a video chip, so the queue can be skimmed by faces. Status pills and the open request live in the URL (`?status=&evaluation=<id>`, so the SMS link and the Back button open the drawer); the drawer is a `Sheet` (a side sheet on desktop, a bottom sheet on phones) with the call button, when the customer is free, photos (with a lightbox) and videos. «ارزیابی شد» asks once; «رد» needs a reason that goes to the customer by SMS. The row's answer buttons start at `lg`; the one-line row at `xl`; on phones the answers live in the drawer's footer.
- Admin Dashboard (`/admin`): `app/routes/admin_index/`. Display only, from one call (`dashboard.admin.overview`): «منتظر توست» (requests to answer, the paid, not enrolled items and the latest five purchases with the customer to call), «ثبت‌نام‌ها» (active, completed, cancelled), «پول» (paid this Jalali month in Tehran time, paid in total, commissions not yet paid) and a table of every course (bought, active, completed). The idea: the board is dark when there is nothing to do; only what waits for him is lit in gold, and a zero is a calm tile. Every number links to its filtered list (`/admin/evaluations`, `/admin/payments?view=flagged|paid`, `/admin/enrollments?status=`); the commissions and the courses have no link until the Partners and Courses pages exist.
- Admin Dogs (`/admin/dogs`): `app/routes/admin_dogs/`. The register: a row per dog with its face, owner (number to call), up to three passed courses and one stamp (`DogEvaluationStamp`: evaluated, waiting for his answer, not yet); the whole row opens Dog Detail. Search (Persian-folded on dog, breed, file number, owner, phone with or without the leading 0), state pills and pages live in the URL (`?q=&state=&page=`).
- Admin Dog Detail (`/admin/dogs/:dogId`): `app/routes/admin_dog_detail/`. The dog's photo, stamp and owner at the start (sticky on desktop), and the **ladder**: a rung per approved course in catalogue order, passed (from an enrollment: final; by hand: «برداشتن علامت»), open, or locked with the API's reasons (the shared «not evaluated» reason is said once, by the evaluation card); «گذرانده علامت بزن» on any unpassed rung. «ارزیابی شد» (with one confirm dialog) marks a dog he already knows as evaluated. The file card (number, QR code, link, PNG) sits under the evaluation card. Enrollments, **the certificates** (a row per completed enrollment: «صدور گواهی», or the number, its state and «باطل کردن»; each asks first), **the diary** (a session is written and corrected in a `Sheet` on `?session=new` or `?session=<id>`) and evaluations are listed (the endings are done on the Enrollments page); the details are edited in a `Sheet` on `?edit=true` (every existing field except the photo, the locked breed and birth date included). The dog's name links here from Enrollments, Payments and the Evaluations drawer.
- Admin Partners (`/admin/partners`): `app/routes/admin_partners/`. The pay sheet: one block per partner who is owed, in the order he works (the Sheba in groups of four with «کپی شبا», the sum due, then a «پرداخت شد» button per commission line with one confirm, which texts the partner), a ledger of paid ones, and the partner roster (`?view=unpaid|paid|partners`). A partner opens in a `Sheet` (`?partner=<id>`: his link and Sheba, his people by stage, his commissions, deactivate or activate); «همکار تازه» (`?new=1`) creates the account (name, phone, optional link code that never changes). The Dashboard's unpaid-commissions row links to `?view=unpaid`.
- Partner Dashboard (`/account/partner`): `app/routes/account_partner/`. The partner's landing page (`roleHomePath`). The shop card is an ivory tile with the referral link's QR (made on the server with `uqr`) that he copies, downloads as a PNG and puts by his till; a funnel strip (numbers, registered, buyers) links to Leads, and his commissions show amount, customer's name and paid or waiting. Notices for a missing Sheba (link to Profile Settings) and an inactive account.
- Leads and Customers (`/account/partner/leads`): `app/routes/account_partner_leads/`. He adds a customer's phone number and each person is a short chalk road of three stops (number, registered, bought) with dates; a lost lead is dimmed, says only «به اسم تو ثبت نشد» and never who won. Stage pills and paging live in the URL (`?stage=&page=`). A number that already has an account is refused when he adds it.
- Admin Users (`/admin/users`): `app/routes/admin_users/`. The roll: a row per person (initial, name, role chip, number to call, registered and last sign-in, dogs for a customer), search, role and status pills (cross-counted) and pages in the URL (`?q=&role=&status=&page=`). A blocked person is dimmed with a dashed border and a «مسدود» chip, the same vocabulary as Leads' lost row. The whole row opens a dialog (`?user=<id>`): fix the name, read-only number and role (one role per number), links to the customer's dogs or the partner's row, and a danger zone: «مسدود کردن» (one confirm; the user is signed out everywhere at once and gets no code) or «باز کردن حساب». The Admin's own row and any admin can't be blocked. Users creates no one and never deletes. Blocking a partner closes his sign-in only; his link and commission are switched off on the Partners page.
- Admin Courses (`/admin/courses`): `app/routes/admin_courses/`. The catalogue as a numbered shelf in the order customers meet it (no URL state): position with up and down arrows, cover, title, facts, «بعد از:», price or «بعد از ارزیابی», and active/total enrollments. «بایگانی» (one confirm; names the on-sale courses that need it as a prerequisite) and «برگرداندن» (no confirm); an archived row is dashed and dim. Courses are never deleted. «دوره‌ی تازه» and «ویرایش» go to the Course Form.
- Admin Course Form (`/admin/courses/new`, `/admin/courses/:slug/edit`): `app/routes/admin_course_form/`, one module with two route ids. Every field the public pages read (name, latin name, family, summary, cover and its alt text, ages in months, sessions, place, price and boarding price in Toman, prerequisites, results and commands one per line), with the real `CourseCard` as a live preview. The slug is chosen at creation and never changes; a cover is uploaded through `media.upload` (kind `course`); a blank price means «بعد از ارزیابی»; a course that already requires this one can't be picked as its prerequisite. Not built, and why: lesson length (no column, owner undecided), breed rules and evaluation tags (course settings pending the owner, F8), drafts, drag to reorder, a leave-without-saving guard.
- Admin Platform Settings (`/admin/settings`): `app/routes/admin_settings/`. Three numbers, each in a card with its default, a live sentence of what it will do («از خریدی به مبلغ ۱۰,۰۰۰,۰۰۰ تومان، ۱,۰۰۰,۰۰۰ تومان پورسانت می‌نویسیم») and its own «ذخیره»: the partner commission percent, sign-in codes per number per hour and per connection per hour. All three are read live (no restart) and the Partner Enquiry page shows the percent in force. The code length, its 2-minute validity, 5 wrong tries and the 60-second wait are fixed in code and the page says so.
- Admin SMS Outbox (`/admin/sms`): `app/routes/admin_sms/`. Read-only: every message the app would have sent (showcase mode sends none), newest first, as a phone-style bubble with the number, a kind chip and the time. The one Admin list paged on the server (`?kind=&page=`), because the outbox gains a row per sign-in code; kind pills show only kinds that have rows, with counts.
